# Baro Architecture

> **Product:** [baro.quest](https://baro.quest) — 한국 크립토 Telegram 커뮤니티의 프로젝트 마인드셰어를 실시간으로 추적하는 인텔리전스 대시보드입니다.
>
> **Documentation version:** v0.1
> **Status:** Working baseline
> **Last reviewed:** 2026-07-30

이 디렉터리는 Baro가 어떤 데이터를 다루고, 어떤 책임을 체인에 남기며, 어떤 결정이 아직 열려 있는지를 정리한 공개 아키텍처 문서다. 피치 자료를 길게 풀어 쓴 문서가 아니라, 제품·개발·운영이 같은 전제를 공유하기 위한 기준점으로 사용한다.

## 이 문서가 다루는 제품 범위

Baro는 한국 Web3 커뮤니티에서 공개적으로 관측되는 Telegram 신호를 정리해, 프로젝트·내러티브·채널의 변화를 탐색할 수 있게 한다. 캠페인 기능은 이 맥락 위에서 참여와 보상을 연결하기 위한 별도 흐름이다. 데이터 수집·해석과 참여 검증은 Baro 애플리케이션에서 수행하고, 보상 예치·클레임·참여 이력처럼 나중에 다시 확인해야 할 사실은 GIWA 호환 EVM 환경에 남기는 방향으로 설계한다.

문서 안의 상태 표기는 구현 현실을 구분하기 위한 것이다. `Current`는 이미 제품 또는 운영 기준으로 쓰는 범위이고, `MVP / Testnet`은 테스트넷에서 검증할 설계 범위다. `Planned`와 `Decision needed`는 아직 확정하거나 구현했다고 말하지 않는 항목이다.

| 상태 | 의미 | 문서에 쓰는 방식 |
|---|---|---|
| `Current` | 현재 제품 또는 운영 기준에 포함된 범위 | 관측되는 데이터와 동작을 설명한다 |
| `MVP / Testnet` | 테스트넷에서 닫힌 흐름으로 검증할 범위 | 배포·테스트 증거가 생기면 함께 기록한다 |
| `Planned` | 다음 단계 후보 | 설계 의도만 쓰고 구현 완료로 표현하지 않는다 |
| `Decision needed` | 팀이 선택을 확정해야 하는 항목 | 선택지와 결정 이유를 남긴다 |

## 핵심 용어

| 용어 | 이 문서에서의 의미 |
|---|---|
| **Baro Intelligence** | 공개 Telegram 채널의 관측값을 모아 프로젝트·내러티브·채널의 변화를 탐색하게 하는 Baro의 인텔리전스 영역이다. |
| **영향력 지수** | 채널의 공개 활동 신호를 바탕으로 Baro가 산출하는 상대적 영향력 지표다. 산출에 쓰는 가중치·임계값·예외 규칙은 공개하지 않는다. |
| **마인드셰어** | 특정 기간에 관측된 공개 신호를 바탕으로 프로젝트 또는 내러티브가 차지하는 관심의 비중을 보여 주는 지표다. 거래량·가격·실제 사용자 수와 같은 의미는 아니다. |
| **Baro Scoring Engine** | 수집된 관측값을 영향력 지수, 마인드셰어, 추세 등 제품용 지표로 변환하는 내부 처리 체계다. |
| **캠페인** | 프로젝트가 보상 예산·기간·퀘스트 조건을 정해 참여를 운영하는 단위다. |
| **퀘스트** | 보상과 연결되는 검증 가능한 참여 행동 또는 완료 조건이다. |
| **채널 운영자 매핑** | 운영팀이 채널 식별자·연락 이력·정산 지갑 등 서로 대조 가능한 정보를 직접 확인해 채널과 운영 주체를 연결하는 절차다. |
| **Campaign Escrow** | 캠페인 예산을 예치하고, 검증된 참여자의 보상 클레임을 처리하는 온체인 모듈이다. |
| **Reputation SBT** | 전송할 수 없도록 설계하는 참여 이력·레퓨테이션 기록이다. |
| **GIWA Sepolia** | Baro의 온체인 캠페인·보상 흐름을 검증하는 GIWA 테스트넷 환경이다. |

## 문서에 남기지 않는 정보

이 저장소는 공개 문서이므로, 제품을 설명하는 데 꼭 필요하지 않거나 운영상 악용될 수 있는 세부 값은 담지 않는다. Baro Scoring Engine의 가중치·임계값·상한·예외 규칙, 원시 Telegram 메시지 전문, API 키와 운영자 키, 개인정보, 내부 운영 대시보드 값은 이 범주에 포함된다.

스코어링이나 검증 정책이 바뀌어도, 공개 문서에는 목적·입력 데이터의 범주·사용자에게 보이는 결과·변경 시점만 반영한다. 실제 매개변수와 재계산 규칙은 접근이 통제된 내부 문서와 코드에서 관리한다.

## 버전과 갱신 기준

이 공개 문서 세트의 현재 버전은 **v0.1**이다. `v0.x`는 제품·컨트랙트·운영 절차가 계속 검증되는 단계의 문서 기준선을 뜻하며, 문서에 적힌 상태 표기와는 별개로 관리한다.

| 변경 유형 | 버전 처리 | 예시 |
|---|---|---|
| 오탈자, 링크, 설명 보완 | `v0.1.x` 패치 | 용어 정의 보완, 잘못된 링크 수정 |
| 시스템 경계, 공개 정책, 인터페이스, 운영 절차의 의미 있는 변경 | 다음 `v0.x` 마이너 버전 | 완료 권한 모델 확정, 새로운 온체인 모듈 추가 |
| 팀이 운영 기준선이 충분히 안정화되었다고 판단한 시점 | `v1.0` 전환 검토 | 테스트넷 검증 결과와 운영 정책을 반영한 기준선 확정 |

문서를 바꿀 때는 해당 문서의 `Last reviewed` 날짜를 갱신하고, 아키텍처에 영향을 주는 결정은 [구현 단계와 결정 기록](./06-delivery-plan-and-decisions.md)에 함께 남긴다.
